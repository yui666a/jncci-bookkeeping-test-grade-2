出題区分表と教材を突き合わせ、抜けている論点を見つける。

## 手順

1. まず機械的な差分を取る。`npm run coverage` を実行する

2. その出力を起点に、機械では出せない判断を加える

- **メタには書いてあるが、本文の扱いが薄すぎる論点はないか。**
  IDを書けばカバー済みと数えられるが、1行触れただけでは学習者は解けない
- **到達チェックの「N項目を列挙できる」のNは必要十分か。**
  区分表の該当項目数と突き合わせる
- **未カバーの論点は、本当にその単元の担当か。**
  `学習カリキュラム.md` の週次配分を見て、別の週に割り当てられているなら
  それは抜けではない
- **本文は扱っているのに、メタに書かれていない論点はないか。**
  これは本文を書き足す話ではなく、メタを直すだけで済む。対応が違うので
  他の未カバーと分けて報告する
- **どの週にも割り当てが見当たらない論点は、判定を保留して挙げる。**
  週次配分は自然文で書かれており論点IDとの対応表がない。単元の抜けなのか
  カリキュラム側の記載漏れなのかは、この情報からは決められない

## 報告の形式

```
メタの宣言漏れ（本文は扱っている）:
  論点ID  タイトル  — 本文のどこで扱っているか

未カバー（この単元が扱うべきもの）:
  論点ID  タイトル  — なぜ必要か

扱いが薄い:
  論点ID  タイトル  — 現状どう触れているか、何が足りないか

別の週の担当（抜けではない）:
  論点ID  タイトル  — 学習カリキュラム.md のどこ

どの週にも見当たらない（判定保留）:
  論点ID  タイトル
```

「扱いが薄い」の判定は、**学習者が本番の設問に答えられる状態かどうか**を
基準にする。行数ではない。

到達チェックの N は、区分表側が内訳を列挙していない項目（`商-第三-3-0 決算整理`
など）とは突き合わせられない。その場合は検証できないと書く。

修正はしない。何を足すかは執筆側の判断である。
