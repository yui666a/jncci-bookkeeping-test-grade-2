# 学習記録の転記

`progress.html` のエクスポートは**常に全期間**を含む。差分は取られていない。
`進捗ログ.md` に既にある日付を二重に書かないよう、追記する範囲はここで判断する。

## 手順

1. `進捗ログ.md` を読み、記録済みの最も新しい日付を確認する
2. 渡された JSON の `exportedAt` を見る。`進捗ログ.md` の最新日付より**古ければ**、
   古いエクスポートを貼られている。転記せず、その旨を伝える
3. 最新日付より**後**の `sessions` / `notes` と、その期間に試行のある `drills` を抽出する
4. 日付ごとにまとめ、`# 学習記録` の見出しの直後に追記する（新しい日付が上）

## 書式

```markdown
## 2026-08-29（金）
学習時間 2h56m（週計 2h56m / 目標 23h）

- phase0/03_dentaku 完了。定数計算は演算キー2回押しの機種だと確認
- 要復習: 勘定連絡図のアップストリーム按分
```

- **学習時間**はその日の `sessions` の `sec` を合計する。週計は月曜起点
- **メモ**は `notes` の `text` をそのまま箇条書きにする。**要約しない。**
  学習者自身の言葉が、後から読み返したときの手がかりになる
- **要復習**は、`attempts` の最後が誤答である設問を挙げる。回数ではなく
  **直近で正解できているか**で判断する。3回間違えて4回目に正解した設問より、
  1回間違えたまま放置している設問のほうが危ない。論点名は単元HTMLの見出しか
  `reference/syllabus.yml` から引く

## 判断が要るところ

**ドリルIDは人間に読めない。** `phase1/01_shou-junshisan-genkin#quiz-chosei/q10`
のままでは、何が分かっていないのか後から読めない。単元HTMLを開いて設問の
内容を確認し、論点の名前で書く。

**同じ日に複数の単元をやっていれば、単元ごとに行を分ける。** 1日1行にまとめると、
どこで時間を使ったかが消える。

**学習時間が極端に短い日（10分未満）は、単独では書かない。** 教材を開いただけの
記録が並ぶと、実際に学習した日が埋もれる。

## やらないこと

- **`localStorage` の内容を推測して補わない。** JSON にないことは書かない
- **学習量への評価や励ましを書かない。** 記録は記録として残す。
  「よいペースです」「遅れています」の類は、後から読むときに邪魔になる
- **既にある日付の記述を書き換えない。** 追記のみ
- **メモの言い回しを整えない。** 「按分が分からない」を「按分の理解が不十分」に
  直すと、書いたときの温度が失われる

## 転記のあとに伝えること

転記した範囲（日付と件数）と、要復習に挙がった論点を短く伝える。
`localStorage` は消えると戻らないので、**転記できた範囲まではバックアップが
取れた**ことが学習者にとっての意味になる。
